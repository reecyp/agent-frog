# AI log: where the system was confidently wrong, and how it was caught

The app writes its own log of flags and student decisions (the **AI log** page, table `ai_events`). This file records the mistakes the team caught while building, written to cover requirement R11.

| # | What went wrong | How it was caught | Fix |
|---|---|---|---|
| 1 | **Overstated ownership.** The rule engine follows the Neeley guide ("avoid weak verbs like Assisted"), so it rewrote *"Assisted with reconciling monthly client billing statements"* as *"Reconciled monthly client billing statements"*. That claims the student did it themselves. | The deterministic validator flagged `ownership_escalation` before the student saw the draft, and the document couldn't be approved until the student confirmed or reverted it. | Kept as designed: style advice can propose, but only the student can confirm a stronger claim. Covered by a test. |
| 2 | **A posting counted as an internship that wasn't.** "International Payroll Analyst" matched an internship filter because "Intern" is inside "International". | The first board probe returned obviously wrong "internship" titles. | Word-boundary matching in `classifyLevel`; regression test. |
| 3 | **A metric invented by the parser.** "Reconciled 120 monthly statements" was read as "120m" (120 million) because the unit pattern swallowed the "m" of "monthly". The warning shown to the student said *"the figure 120m"*. | Seen in the review panel while testing the edit-and-recheck flow. | Units now need a word boundary; regression test. |
| 4 | **Strong fit for jobs the student can't get.** MS/PhD internships were rated a strong fit for an undergraduate because their requirements overlapped. | Visual review of real search results. | Graduate-degree titles now subtract points, with the reason shown as a fit factor. |
| 5 | **A thin cover-letter connection.** The rule-based letter paired a volunteer mentoring bullet with "Support a defined roadmap project end-to-end" because of one shared word. | Reviewing a generated letter in the proof sheet. | Cover-letter pairings now need a stronger match (score of 3 or more); otherwise the paragraph is a visible blank for the student to write. |
| 6 | **Search showed no Texas results.** It looked like a filtering bug. | A trace of each rejected posting showed the filter was right: there were no Dallas or remote finance internships on those boards in October. | Kept the filter; added an honest near-miss count with a one-click widen, and widened "Dallas" to the DFW metro. |
| 7 | **PDF read as one word per line.** The exported resume looked correct, but an independent parser (pypdf) extracted each word on its own line, which can confuse an applicant tracking system. | The team's own reading-order check ignored whitespace, so it passed. Re-reading the PDF with a different library exposed it. | The renderer now writes each line as one text run; a new test asserts whole phrases extract intact. |

Pattern: every catch came from a check that doesn't trust the generator, whether a deterministic rule, a second tool, or a person reading real output. That is the design principle of the honesty pipeline.
